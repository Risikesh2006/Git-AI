# Deployment Guide

Everything in this repo is ready to deploy — config files, migrations, CI, and the
render/vercel blueprints. What's left is account setup and secrets, which need a
human with access to real accounts. This is that checklist.

## 1. Supabase (database + auth) — do this first, everything else needs its URL/keys

1. Upgrade the project to a **paid tier** before real traffic — the free tier pauses
   after a week of inactivity, which would silently take the whole app down.
2. Run the migration: **SQL Editor → paste `supabase_schema.sql`, then
   `supabase/migrations/0001_production_readiness.sql`, in that order → Run.**
   (Going forward, add new schema changes as new files under `supabase/migrations/`
   rather than editing `supabase_schema.sql` in place — see Phase 7 in the roadmap.)
3. **Authentication → Providers → GitHub → Enable**, using the OAuth app from step 2 below.
4. Note down from **Project Settings → API**: Project URL, anon key, service role key.

## 2. GitHub OAuth App

1. **GitHub → Settings → Developer settings → OAuth Apps → New OAuth App.**
2. Homepage URL: your production frontend URL (from step 4). Callback URL:
   `https://<your-backend-domain>/api/auth/callback`.
3. Put the Client ID/Secret into Supabase's GitHub provider settings (step 1.3).

## 3. Anthropic API key (cloud LLM fallback)

1. Create a key at [console.anthropic.com](https://console.anthropic.com).
2. This is the one paid, usage-based dependency in the stack — the app calls it only
   when a user's local LM Studio is unreachable. `backend/services/ai.js` already
   tracks per-call cost into the `usage_events` table; keep an eye on it early on.

## 4. Backend + ML service — Render

1. **New → Blueprint**, point it at this repo — it reads `render.yaml` and creates
   `gitai-backend` and `gitai-ml-service`.
2. Fill in every env var marked `sync: false` in `render.yaml` (Supabase keys, GitHub
   OAuth secret, Anthropic key, `FRONTEND_URL`). `JWT_SECRET` and
   `TOKEN_ENCRYPTION_KEY` are auto-generated by Render — leave those.
3. After both services are live, copy the ML service's internal host:port from the
   backend's Environment tab and set `ML_SERVICE_URL` to `http://<that value>`
   (see the comment in `render.yaml` for why this can't be templated automatically).
4. **Settings → Deploy Hook** on each service → copy the URL → add as repo secrets
   `RENDER_BACKEND_DEPLOY_HOOK` / `RENDER_ML_SERVICE_DEPLOY_HOOK` in
   **GitHub → Settings → Secrets and variables → Actions**. This is what makes
   `.github/workflows/deploy.yml` actually redeploy on merge to `main`.
5. Before going live: train the model and confirm the artifacts are in `models/`
   (`cd ml && python train.py`) — the ML service needs them at boot. They aren't
   committed to git (binary artifacts); Render's build step should regenerate them,
   or upload them as a Render disk / persistent mount if you'd rather not retrain
   on every deploy.

## 5. Frontend — Vercel

1. **Import Project** from this repo. Set **Root Directory** to `frontend`.
2. Env vars: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (from step
   1.4), `NEXT_PUBLIC_API_URL` (the Render backend's public URL).
3. Vercel auto-deploys on every push to `main` once connected — no extra workflow needed.

## 6. Observability

1. Create a Sentry project (Node platform for backend, Next.js for frontend).
2. Backend: `npm install @sentry/node` in `backend/`, set `SENTRY_DSN` in Render.
   (`backend/services/errorTracking.js` is already wired to pick it up — it no-ops
   until both the package and the env var are present.)
3. Point a free uptime monitor (UptimeRobot, Better Stack) at
   `https://<backend-domain>/api/health` and `https://<ml-service-domain>/health`.

## 7. Smoke test before opening it up

1. Sign in with GitHub through the deployed frontend.
2. Scan a repository — confirms Supabase, GitHub OAuth, and the ML service (or its
   JS-heuristic fallback) all work end to end.
3. Generate a daily plan — confirms the AI backend (LM Studio or Claude fallback)
   and `/api/ai/status` correctly reports which one answered.
4. Propose a small file change in the Commit Assistant, approve it, confirm the
   commit and (optionally) PR land on GitHub — this is the highest-blast-radius
   path in the app and the one most worth checking by hand before real users touch it.

## What this repo cannot do for you

No deploy account, hosting credential, or API key can be created by an AI agent —
every step above that says "create," "set," or "copy a secret" needs a human at a
keyboard with access to your Supabase/GitHub/Render/Vercel/Anthropic accounts.
